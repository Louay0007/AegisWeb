\section{What is \ProductName?}

\ProductName\ is a control plane for AI agents that act on vendor websites.
Instead of giving an agent unmanaged access to billing portals, the platform:

\begin{itemize}[leftmargin=1.2em]
  \item assigns each agent an identity and purpose;
  \item stores credentials in a vault and grants them selectively;
  \item evaluates actions against policies;
  \item pauses risky work for human approval;
  \item records immutable audit events and evidence receipts.
\end{itemize}

This demo is already seeded with a realistic organization, agents, vendors,
credentials, workflows, historical runs, one pending approval, receipts, and
an audit hash chain---so you can explore the product without building data from
scratch.

\begin{callout}[Demo intent]
  Treat this as a shared sandbox. Feel free to start runs, approve or reject
  requests, and inspect receipts. Prefer the guided scenarios below so other
  testers can still follow the happy path.
\end{callout}

\section{Core concepts (2-minute glossary)}

\begin{description}[style=nextline,leftmargin=1.4em,font=\bfseries\color{aegisblue}]
  \item[Agent] A governed automation identity (for example \emph{Procurement Bot}).
  \item[Vendor] A SaaS / web portal the agent may visit (Acme, Nimbus, Atlas,\ldots).
  \item[Credential] Vault-stored login secret, granted only to selected agents.
  \item[Policy] Rules that allow, deny, or require approval for actions/domains.
  \item[Workflow] A reusable template binding agent + vendor + credential.
  \item[Run] One execution of a workflow.
  \item[Approval] Human decision when policy marks an action as risky.
  \item[Receipt] Evidence package for a finished run (status, files, decisions).
  \item[Audit] Append-only event log with hash-chain verification.
\end{description}

\section{Scenario A --- Flagship approval path (recommended)}

This is the best end-to-end demo of \ProductName.

\begin{enumerate}[leftmargin=1.3em]
  \item Open \url{\DemoAppUrl} and sign in as
        \email{founder@northstarlabs.dev} / \texttt{\DemoPassword}.
  \item Go to \ui{Runs} $\rightarrow$ \ui{Start workflow}
        (or open \ui{Workflows} and start from there).
  \item Choose \textbf{Acme Downgrade Request}.
  \item Confirm the agent, vendor, and credential, then start the run.
  \item Watch the run move to \textbf{Waiting for approval}.
        The worker logs into the Acme sandbox, prepares a plan change, and
        pauses because policy requires human approval.
  \item Optional: open \url{\DemoMailUrl} and confirm an approval notification
        was sent (if mail capture is enabled on this deployment).
  \item Sign out, then sign in as
        \email{finance@northstarlabs.dev}.
  \item Open \ui{Approvals}, select the new request, review the summary and
        screenshot, then click \ui{Approve} (or \ui{Reject} to see the denial path).
  \item Switch back to the owner (or stay as finance if permitted) and open
        \ui{Runs}: the run should resume and reach \textbf{Completed}.
  \item Open \ui{Receipts} for screenshots / summary evidence, then \ui{Audit}
        to inspect the event trail and verify the hash chain.
\end{enumerate}

\begin{callout}[Success criteria]
  You should see: queued $\rightarrow$ running $\rightarrow$ waiting for approval
  $\rightarrow$ (after approve) completed, plus a receipt and audit events for
  approval and completion.
\end{callout}

\section{Safety \& privacy}

\begin{itemize}[leftmargin=1.2em]
  \item Credentials in the vault are encrypted; UI and receipts redact secrets.
  \item The Acme / Nimbus / Atlas / Payroll portals are a \textbf{vendor sandbox},
        not real customer systems.
  \item Stripe Billing and GitHub rows are typed connectors with placeholder
        passwords---live execution against real sites is out of scope for casual
        public testing.
  \item Audit events are append-only; verifying the chain should succeed for the
        seeded organization unless data was tampered with.
\end{itemize}

\section{Troubleshooting}

\begin{description}[style=nextline,leftmargin=1.2em,font=\bfseries]
  \item[Cannot log in]
    Confirm you use a seeded email and \texttt{\DemoPassword}. Caps Lock and
    autofill of an old password are common issues.
  \item[Run stays queued]
    The worker may be restarting or overloaded. Wait ~30\,s, refresh \ui{Runs},
    then check with the demo operator if it remains queued.
  \item[Run fails immediately]
    Open the run detail for \texttt{errorMessage}. Typical causes: paused agent,
    missing credential grant, or sandbox unavailable.
  \item[No approval appears]
    Confirm you started \textbf{Acme Downgrade Request} (invoice download does
    not pause). Refresh \ui{Approvals} while signed in as finance.
  \item[Approve does nothing]
    Ensure you are \email{finance@northstarlabs.dev} (or another user with
    approval permission). Owner accounts may be able to start runs but the demo
    is designed around the finance approver for the happy path.
  \item[HTTPS / certificate warning (local demos only)]
    Local stacks using an internal CA may show a browser warning---use
    Advanced $\rightarrow$ Proceed, or install the operator-provided root CA.
\end{description}

\begin{enumerate}[leftmargin=1.3em]

\end{enumerate}
